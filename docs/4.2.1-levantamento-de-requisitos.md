# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos foram levantados por meio de uma conversa com o dono do mercado, buscando entender as principais dificuldades no controle dos produtos. Foram registradas as necessidades relacionadas ao cadastro, consulta, alteração e exclusão de produtos, além do controle de entradas, saídas e relatórios do estoque.

❓ **A confirmar com o cliente:** quais informações específicas devem ser cadastradas para cada produto.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Preciso controlar melhor os produtos do meu mercado." (dono do mercado) | necessidade | Ter controle organizado dos produtos. |
| F2 | "Quero saber o que entra e sai do estoque." (dono do mercado) | necessidade | Acompanhar a movimentação dos produtos. |
| F3 | "Preciso saber a quantidade de cada produto disponível." (dono do mercado) | necessidade | Consultar a quantidade atual dos produtos. |
| F4 | "Quero manter os produtos cadastrados e atualizados." (dono do mercado) | necessidade | Manter as informações dos produtos corretas e atualizadas. |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como dono do mercado, quero cadastrar produtos, para manter os produtos do mercado registrados. | F1 |
| HU02 | Como dono do mercado, quero consultar produtos, para saber quais produtos estão cadastrados e suas quantidades. | F3 |
| HU03 | Como dono do mercado, quero alterar e excluir produtos, para manter o cadastro atualizado | F4 |
| HU04 | Como dono do mercado, quero registrar entradas e saídas, para acompanhar a movimentação do estoque. | F2 |
| HU05 | Como dono do mercado, quero gerar relatórios do estoque, para acompanhar as informações dos produtos de forma organizada. | F1 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar Produto | O sistema deve cadastrar produtos. | HU01 |
| RF02 | Consultar Produto | O sistema deve consultar produtos cadastrados. | HU02 |
| RF03 | Alterar Produto | O sistema deve alterar os dados dos produtos. | HU03 |
| RF04 | Excluir Produto | O sistema deve excluir produtos cadastrados. | HU03 |
| RF05 | Registrar Entrada | O sistema deve registrar entradas de mercadorias. | HU04 |
| RF06 | Registrar Saída | O sistema deve registrar saídas de mercadorias. | HU04 |
| RF07 | Consultar Estoque | O sistema deve consultar as quantidades disponíveis dos produtos. | HU02 |
| RF08 | Gerar Relatório | O sistema deve gerar relatórios do estoque. | HU05 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | Usabilidade | O sistema deve apresentar informações de forma simples e fácil de entender. | Características da 4.1 |
| RNF02 | Segurança | O sistema deve permitir que apenas usuários autorizados alterem ou excluam produtos. | Características da 4.1 |
| RNF03 | Desempenho | O sistema deve apresentar as consultas do estoque em até 3 segundos. | Características da 4.1 |
| RNF04 | Armazenamento | O sistema deve armazenar os dados dos produtos de forma organizada e segura. | Características da 4.1 |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| O sistema cadastra produtos. | RF01 |
| O sistema consulta produtos e quantidades em estoque. | RF02, RF07 |
| O sistema altera os dados dos produtos. | RF03 |
| O sistema exclui produtos cadastrados. | RF04 |
| O sistema registra entradas e saídas de mercadorias. | RF05, RF06 |
| O sistema gera relatórios do estoque. | RF08 |

Todas as histórias de usuário possuem pelo menos um requisito funcional relacionado, e todos os requisitos funcionais possuem uma história de usuário como origem. A conferência também mostrou que todos os itens do escopo da 4.1 estão representados nos requisitos._
